# Architecture

One Next.js 16 App Router application (TypeScript, React 19) with Payload CMS 3.90 mounted at `/admin` and PostgreSQL through `@payloadcms/db-postgres`. pnpm, Tailwind v4 (utility layer only; the site uses plain CSS custom properties in `src/app/(frontend)/globals.css`).

```
src/
  app/(frontend)/            public site
    page.tsx                 homepage conversation (no shell)
    layout.tsx               fonts, theme attributes from Appearance, admin bar
    (site)/                  sidebar shell: projects, blog, about, research, contact, [slug]
    sitemap.xml, rss.xml, robots.txt, next/preview
  app/(payload)/             Payload admin and REST/GraphQL API (template)
  collections/               Projects, Posts, Pages, Publications, Experience, Education, Certifications, Media, Categories, Users
  globals/                   Homepage, Navigation, About, Appearance, SiteSettings
  blocks/                    block configs and the template block components
  components/home            Conversation (server) + ConversationPlayer (client, anime.js)
  components/projects        ProjectExplorer (client), ProjectGrid
  components/blocks          RenderProjectBlocks (whitelisted block renderer)
  components/shell           Sidebar, Topbar, NavLinks, PageTransition (exit-then-navigate on internal links)
  data/                      content.ts (loaders → view models), types.ts, media.ts
  styles/theme.ts            Appearance whitelist → data attributes
  hooks/revalidate.ts        afterChange hooks → revalidatePath
  seed/                      verified initial content and the seed runner
```

## Data flow
Pages are server components that call Payload's local API through `src/data/content.ts` and map documents to small view models. Every public page is `force-dynamic`, so a publish is visible on the next request; the hooks in `src/hooks/revalidate.ts` additionally clear Next's data cache for the affected paths. There is no scheduled delay.

Draft mode (`/next/preview?path=…&previewSecret=…`) switches the loaders to `draft: true`, which powers Payload live preview for projects, posts, pages, the homepage and the About global.

## Security
- Admin authentication and access control are Payload's. Public registration is off: `Users` is admin-only, and the first user is created once through `/admin/create-first-user`.
- Public reads use `authenticatedOrPublished`; drafts never reach anonymous requests.
- Rich text renders through Payload's Lexical React converter. The only user-controlled embed is the `embed` block, which rejects hosts other than YouTube and Vimeo and renders `youtube-nocookie.com` / `player.vimeo.com` iframes.
- Inline links in homepage messages must be relative, `https:`/`http:` or `mailto:`; anything else renders as plain text.
- CMS pages cannot claim reserved application paths (`src/utilities/reservedSlugs.ts`, enforced in a `beforeValidate` hook and again in the route).
- Uploads are limited to images, MP4, WebM and PDF; Payload validates MIME type and size.
- Secrets come from the environment only (`.env.example`); nothing is committed.

## Media
Locally, uploads land in `public/media`. In production set `BLOB_READ_WRITE_TOKEN` and the Vercel Blob adapter takes over the `media` collection (persistent object storage). Image sizes are generated by sharp (thumbnail, square, small, medium, large, xlarge, og).

## What was deliberately not built
- A contact form. Site settings has a `contactFormEnabled` flag and the form-builder plugin is installed, but no email provider is configured. Enable it only after adding an email adapter.
- Three.js. Nothing in the brief needs it.
- Scheduled publishing UI beyond Payload's built-in `schedulePublish` on projects.
